# Editorial template synchronization

## Baseline

- Repository: <https://github.com/Galaxy-Dawn/academic-homepage-templates>
- Branch: `main`
- Source directory: `themes/editorial`
- Reviewed upstream commit: `665e3646275176c420e1cf6ce8043a86798e660b`
- Extracted Editorial tip: `395bd0d6046094ca17dfb07468a87972184990b1`
- Personal site before synchronization: `14a7828c1528f9f3362014feb870bdfb4dad12ce`

The extracted tip is generated by `git subtree split --prefix=themes/editorial`.
It contains only the selected theme, with its files mapped to the root. It is a
parent of our first synchronization commit. The extraction is deterministic when
run without extra options; use the same prefix and no `--annotate`, `--onto` or
other history-changing options for future updates.

## First synchronization decisions

- The existing stylesheet already incorporates the current upstream Editorial
  CSS. Differences are the green palette, moved accessibility rules, footer links
  and personal content styles. Preserve `style.css` byte for byte.
- Keep `index.html` byte for byte: personal content, Conference/Journal grouping,
  Teaching/Work experience, removed Projects section, About label, social metadata
  and decorative SVG accessibility attributes are intentional customizations.
- Adopt the current upstream `script.js`, including its optional configuration
  renderer. Keep configuration disabled as described in README.md.
- Fix the shared upstream anchor bug: `href="#"` must not reach
  `querySelector('#')`, which throws before the later placeholder handler can run.
  Resolve nonempty fragments by ID rather than interpreting them as CSS selectors.
- Keep the existing light-mode default, which matches current upstream.
- Restore upstream's complete MIT notice and add upstream's `.nojekyll` marker.
- Theme-gallery iframe transitions, other themes and screenshot updates do not
  apply to this single-theme homepage.

Joining history records a reviewed, customized integration, not byte-for-byte
equality with the template. No evidence of the specific intermediate fork remains
in the personal repository's independent Git history.

## Future updates (PowerShell)

Start from a clean checkout. Add the remote once per clone (skip this command if
`git remote -v` already lists `upstream` with this URL):

```powershell
git remote add upstream https://github.com/Galaxy-Dawn/academic-homepage-templates.git
```

Fetch the latest site and template, then extract the theme in a temporary worktree.
Use a fresh worktree path and synchronization branch name for each update:

```powershell
git fetch origin
git fetch upstream
git switch -c sync/editorial-update origin/main
git worktree add --detach ../editorial-upstream-review upstream/main
$editorialTip = git -C ../editorial-upstream-review subtree split --prefix=themes/editorial
if ($LASTEXITCODE -ne 0) { throw 'Editorial history extraction failed' }
git merge --no-ff --no-commit $editorialTip
```

If Git reports already up to date, there is no new theme history to integrate.
Otherwise review the changes and resolve conflicts individually. Do not blindly
replace personal files with the template or accept every conflict from one side.
The upstream placeholder `config.js` was intentionally removed, so updates to it
can produce a modify/delete conflict; keep it removed unless undertaking an
explicit content migration. Check root-level upstream LICENSE and `.nojekyll`
separately, because subtree extraction only tracks the selected directory.

Update this document's upstream commit and extracted tip using
`git rev-parse upstream/main` and `$editorialTip`. Then:

```powershell
node --test tests/navigation.test.cjs
git diff --check
# Preview the site and verify content, domain, photo, themes and mobile layout.
git add --all
git commit -m "Merge reviewed Editorial template updates"
git push -u origin sync/editorial-update
# Open a PR against main and merge it with Create a merge commit after review.
git worktree remove ../editorial-upstream-review
```

Use `git merge --abort` to abandon an unfinished merge. Do not force-push or
rewrite the deployed branch. Changing GitHub's fork network or recreating the
repository is unnecessary for this synchronization method.
